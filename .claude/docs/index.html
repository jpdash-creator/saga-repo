How the Starward Saga agents and commands fit together

Two layers work together on this project. 4 agents under .claude/agents/ do the actual thinking — planning, drafting, auditing, scoring. 45 slash commands under .claude/commands/ are the orchestration layer: each one is a fixed sequence that invokes agents (and, in a few cases, authorized Python scripts) in a specific order, so the same operation always happens the same way. This page maps every one of them and how they chain together.

First session

The shortest path from a clean checkout to a written Area: the exact commands, the tokens you answer with, and about how many questions each step puts to you. The question counts are a guide, not a rule; a longer Chapter or a busier scene asks more.

Seven steps to your first written Area

FIRST RUN
  1. Install the writer's library, once. pip install -r .claude/tools/requirements.txt installs python-docx, which the .docx writer needs. For icons made in svg mode also run pip install cairosvg. Questions: none.
  2. Make the two icons. /create-image-phase 1, then /create-image-section 1 1. The opening pages of the book carry both; /start-story checks for them first and stops if one is missing. Questions: about 2 per command (the mode and what it will use, then whether to replace an icon that already exists).
  3. Start the story. /start-story builds three specs with you, in this order: the Section Spec for Section 1 (/section-spec build, which reads all of Part 30; Section 1 carries its own epigraph line, asked like any Section's, and the book's first title page prints it below the Phase epigraph, a line kept in Part 30 that reads unset until you give the text; the command asks you once, in plain words, what the Phase line reads now and whether to give or change it (you type the text, and a SKIP leaves the line as it is)), then the Novel-Part Spec for Novel-Part 1 (/part-spec build), then the Chapter 1 Spec (/chapter-spec build). Each one asks its own direction questions and stops for its own spec token: [CONFIRM SPEC], [REVISE SPEC] or [SKIP SPEC]. Only one is open at a time, and a [SKIP SPEC] saves that spec as a draft and stops the chain there. There is no quick mode: each build keeps asking until nothing is left to steer, then makes a last check and asks you for a plain "nothing further" before the token. Questions: no fixed count; rounds of up to four at each of the three levels (direction and themes at Section and Novel-Part, then at Chapter level the opening beat and about three per Area: size and pacing, opening, closing).
  4. Answer for Area 1. Pacing and size are not asked: the Chapter Spec carries them for every Area. /start-story drafts Area 1, audits it and prints the full text. Answer with a Gate 1 token: [CONFIRM WRITE], [REVISE AREA] or [SKIP WRITE]. If a character's conduct moves off the profile you also get a Check #21 question, answered with [KEEP PROFILE], [EVOLVE], [REVISE AREA], [PROVISIONAL] or [DEFER]. Questions: 0 to 2 before the draft, then the one Gate 1 reply (0 to 2 Check #21 questions).
  5. Write the rest of the Chapter. By default, /create-chapter writes the whole Chapter in one cycle after the build plan you confirm (Amended 2026-10-07); you answer with [CONFIRM WRITE], [REVISE CHAPTER] or [SKIP WRITE] on the staged text. To build a Chapter by Area instead, name by-area at the spec or ask for it, then use /next-area.
  6. Write each next Area (by-area Chapters). /next-area, once per Area. It asks branch questions only for what the spec leaves open or what is new, then the Gate 1 reply. Add [NO CONSULT] to the call (/next-area [NO CONSULT]) to skip the branch questions for that one Area. Questions: 0 to 4 before the draft, then the Gate 1 reply.
  7. Check where you are. /status shows the position, the open ledger obligations and the Section density trend. It only reads. Questions: none.
The three token sets. Spec: [CONFIRM SPEC] [REVISE SPEC] [SKIP SPEC] (the same three for a Section Spec, a Novel-Part Spec and a Chapter Spec; the prompt names which one, such as "Section Spec 1.2", "Novel-Part Spec 1.2.3" or "Chapter Spec 1.2.3.004"). Area Gate 1: [CONFIRM WRITE] [REVISE AREA] [SKIP WRITE] (for a whole Chapter, [REVISE CHAPTER] in place of [REVISE AREA]). Check #21: [KEEP PROFILE] [EVOLVE] [REVISE AREA] [PROVISIONAL] [DEFER]. In a consultation question, the option SKIP — let AI decide hands that one question to the AI; it never replaces a token.

Layer 1 — The Specialists

Agents

Every command ultimately delegates real judgment to one of these four. None of them invoke each other directly — the invoking command always orchestrates the hand-offs, in the fixed order described in each command's card further down. While working, each agent reports milestone progress to "main" via SendMessage, and the orchestrating command relays those reports to the author (guardrails/commands/guardrail-plan-then-auto-execution.md).

outline-planner

AGENT
model: claude-sonnet-5-5 effort: max tools: Read · Write · Grep · Glob · SendMessage memory: project

Decides what happens next — at whatever granularity is asked for (Area, Chapter, Novel-Part, Section, or Phase) — before Area Maker drafts anything. This is genuine ambiguity-resolution work (competing valid directions, pacing tradeoffs, cross-Part dependencies), which is why it runs at max effort. It also builds each level of the spec chain (Section Spec, Novel-Part Spec, Chapter Spec), one planner per level.

Reads before planning

  • Guardrails index, authority-tier & domain-ownership, locked-vs-negotiable canon
  • Current position on disk (never a remembered position) + Part 30 / Part 2 consolidated skills; the whole of Part 30 for a Section Spec build
  • Part 36 Areas 4, 12, 17 and 18 to 27 (the Areas that shape a plan) and the whole spec chain above the level it builds, read in full (a Chapter Spec build reads the Section Spec and the Novel-Part Spec, then the Chapter's Area block). The one exception is planning a single Area: there it is a per-Area agent and reads the Chapter Spec in full plus only the Novel-Part Spec's header and closing-state blocks, not the Section Spec
  • Relevant story-memory/ledger-*/ entries for every entity in scope
  • The Current Position block of ledger-worlds-calendar/_index.md and the row of the Open Chapter: the story clock a date is planned from (Part 41)

Hard boundaries

  • Respects the Phase 1 8-Section lock and Locked Canon — won't plan around it
  • Decides what scene happens next, never how a fight resolves (that's audit-time territory)
  • Surfaces canon-structural tradeoffs instead of silently picking a direction
  • Never presents naming a person, thing, place or move as a cost: the named version is its recommended default (Part 28 Rule 20.9). Writes named items in italic in every spec
  • Plans a monster by its Kind's twelve traits, as wild pressure and never a villain; never plans a sentient monster into Phase 1 (Law P30-L9, save the one narrow artifact-made exception of Canon Amendment 2026-10-19 (Law P30-L9)); defines the Kind of the Phase 1 beasts at the Chapter Spec (Part 40)
  • Plans the date of each Area from the Area block's in-story time and the recorded story clock, and writes every window of the spec chain as dates plus Phase Day (cited from Part 41, never copied); an open in-story time is asked at Step 0 and never filled by the planner (Part 41)
  • Carries each Area's size target (1,600, 1,800 or 2,000 words) and pacing from the Chapter Spec and never asks for them again at writing time
  • Never writes a spec file, never confirms its own build, and never writes an epigraph; the command writes the files, and only you may defer a question
Hands the confirmed plan to area-maker. Does not draft, audit, or update ledgers itself.

area-maker

AGENT
model: claude-sonnet-5-5 effort: max tools: Read · Write · Grep · Glob · SendMessage memory: project

Writes the actual prose of the novel — exactly one Area per /next-area invocation, never more; in Chapter mode (Amended 2026-10-07) one instance drafts a whole Chapter for /create-chapter. Drafts from the Outline Planner's confirmed plan; never decides structure and never audits its own output.

Reads before drafting

  • Locked-vs-negotiable canon, prohibited creative acts, Tier-0 narrative quality
  • Voice-first block, before any ledger: Part 36 in full, the plain-words guardrail, Part 28 Areas 4 and 13, Part 29 Area 4, Part 39's POV and Head Tests, then the Chapter so far (every earlier Area of the Chapter, and the last Area of the previous Chapter when this is the first)
  • Pre-Write Ledger Check on every entity that will appear
  • The Chapter Spec in full, plus the Novel-Part Spec's header and closing-state blocks. The Section Spec is not part of a per-Area read: the Chapter Spec carries what the upper specs settled, with its source recorded in its Audit and Settlement Notes
  • The relevant Parts' consolidated skills, via skill-index.json
  • The Current Position block of ledger-worlds-calendar/_index.md and the row of the previous Area, so the date line is set from the recorded story clock and never from memory (Part 41)

Hard boundaries

  • Must be a living scene, not a technically-correct lecture (Part 36)
  • Knows the Part 35 density readings as information; the Chapter Spec decides what the scene holds
  • Never contradicts Locked Canon or anything already accepted in prior Areas
  • Sets a named item (an apparatus, tool, remedy, system, food, drink, dress, relic and the like) in italic at every mention, with a plain article before it, in roman inside speech; sets a named map or document in italic and an agreement, treaty or accord in roman; keeps Named Moves bold-italic; hands over the new items, documents, agreements and Named Moves for the Gate 2 registers (Part 28 Rule 20.8, Part 6 Rule 6.5)
  • Writes a monster as its Kind records it (twelve traits shown in conduct, name in roman, no speech from a beast), stops where a Tier C or D monster reaches one of the four triggers for your ruling, and hands over the new monsters for Gate 2 (Part 40)
  • Writes to the size target the Chapter Spec names (1,600, 1,800 or 2,000 words; passing range 1,280 to 2,400. A count outside 1,280 to 2,400 words is a blocking finding: the write waits for the author to confirm the Area or send it back.) and carries the spec's pacing; an Area is the written unit, a complete scene or one part of a scene that continues across Areas, and an Area that continues the previous one opens in motion from the exact state it left
  • Opens every Area with its date line, one wholly italic paragraph directly under the Area Title Block, written *Year 1247, <Month>, <Weekday>, Day 27* (a range, with the weekday at both ends, when the Area crosses days), taken from the plan and the recorded story clock; sets every other month and weekday name in roman; the line is not narration, so it is counted in nothing; hands over a CALENDAR (this Area) block for the checker (Part 41)
Hands the draft to continuity-checker for Gate 1. Does not write the final file itself — that happens via authorized scripts at Gate 2.

continuity-checker

AGENT
model: claude-sonnet-5-5 effort: max tools: Read · Write · Edit · Grep · Glob · SendMessage memory: project

The audit and ledger-update authority. Cross-references canon skills, story-memory ledgers, and written Areas every time, then verifies. It is the only agent that writes ledger entity files.

Forced-read discipline (non-negotiable)

  • Physically re-reads canon-manifest/*.json from disk — never from memory — at Pre-Area Read, Gate 1, and Gate 2

What it runs

  • Gate 1 — Post-Draft 24-check audit on the new Area; a single FAIL blocks [CONFIRM WRITE]. Check #18(a) asks whether the spec chain is in force: the Chapter Spec, its Novel-Part Spec and its Section Spec all CONFIRMED or COMPLETED. A link that is missing, DRAFT or RETIRED is a Critical FAIL; one that is AMENDED-PENDING-RECONFIRM is a Major FAIL
  • Spec-chain light audit and final sweep — report-only, once per level (Section Spec, Novel-Part Spec, Chapter Spec) before [CONFIRM SPEC]; it also re-lists every SKIP and every deferral so you get a last chance at them. It writes nothing
  • Area flow review — every Gate 1 also reads the Areas already written in the scene (the Chapter so far where the scene continues) as one flow (Check #16, dimension 16-J): breaks of time, place, viewpoint or character state block; sameness is reported with quoted lines and the author rules
  • Threshold consultation — numbers are guide posts, not physics: a computed value crossing a stated line is shown as information in the audit report, never silently remedied and never a fail, a block or a question on its own
  • Gate 2 — Post-Write re-verify + Completeness Indicator + Tier Scope Brackets
  • CCIA — governance/structure integrity · FCIA — 16-dimension narrative audit · ALCA — ledger/rule correctness
  • Ledger updates — Pre-Write Check + Post-Write Update against story-memory/ledger-*/, including a row for every named item in ledger-named-items and for every Named Move in ledger-named-moves and in each user's character-ledger entry, a row for every named document and every named agreement, treaty or accord in ledger-society-information, the monster Kinds and Tier C and D monsters in ledger-character-monster, and the dating of each Area in ledger-worlds-calendar (Area row, the rollups and the Current Position block)
  • Monsters (Part 40) — Gate 1 Check #11 element 11-3 also reads Law P30-L9 (no sentient monster in Phase 1, save the one narrow artifact-made exception of Canon Amendment 2026-10-19 (Law P30-L9)) and Check #20 reads monster traits in light form; the count stays 22; ledger-character-villain is arranged by Tier A to D (Part 18 Area 6.3)
  • Named-item form (Part 28 Rule 20.8) — Check #12 also fails a named item that is not italic (or is italic inside an italic span, or bold, or carries its article inside the name); relics and artifacts are items and are italic; a named document is italic and an agreement is roman; Check #5 reads an item's roman name inside speech as lawful; the count stays 22
  • Date line (Part 41) — Check #11 element 11-2 also reads the Area's date line under the six dating readings (a date never runs backward without a lawful cause, an Area starts on the day the one before it ended, the windows nest, the month is in the table, the weekday is the one the formula gives, ages and festival days agree); Check #12 also reads the line's italic form and the roman form of month and weekday names elsewhere; a failure of either FAILs, and a planned step back at a "cut to another thread" Area is information only; the Position Header carries a Calendar line; the count stays 22 and the six elements of Check #11 stay six. The line is not narration for Checks #10, #16, #19 and #22
Never resolves a conflict itself — surfaces it via AskUserQuestion. Logs every outcome to session-log/ (but never reads that log back as a decision input).

Layer 2 — The Workflow

The Core Two-Gate Pipeline — /next-area

This is the workhorse every Area-producing command eventually calls. It's the exact sequence /next-area runs, and what every Structural Advance command and Revision command re-enters. Nothing gets written to disk without passing Gate 1 clean and receiving an explicit human confirm. The full text of the Area is printed in chat before every confirmation, and each Gate 1 also reviews the Areas already written in the scene as one flow. Execution shape — mandatory parallelism, no clock-based delay, milestone progress reporting — is governed by guardrails/commands/guardrail-plan-then-auto-execution.md.

Loop-backs on the left both re-enter at area-maker: a Gate 1 FAIL and a [REVISE AREA] return to drafting, then re-audit through the same Gate 1 — never onward with a FAIL outstanding. outline-planner is not re-entered mid-cycle; a density reading is recorded in the audit report as information instead (next-area.md Step 3). Gate 1 runs two read-only checker instances together: the 24 checks on the new Area and the Area flow review of the Areas already written in the scene (continuity breaks block; sameness is reported with quoted lines). Pacing and size are not asked: the Chapter Spec carries them. Any question about the draft is asked after the full text has been printed in chat; a [REVISE AREA] re-audits and prints the revised text in full again; [SKIP WRITE] discards everything. At Gate 2 the three lanes are launched in a single message and run concurrently; their outputs are presented in canonical order — Completeness Indicator, Tier Scope Brackets, the CDL-2 block, then the Voice and Variety block — once all three return. Every Area opens with its date line (Part 41): Gate 1 reads it (Check #11 element 11-2 for the dates and the weekday, Check #12 for the italic form) and shows it on the Calendar line of the Position Header; the Gate 2 ledger lane records it in ledger-worlds-calendar.

/create-chapter

C-42
token: [CREATE CHAPTER]

The default path (Amended 2026-10-07). Writes a whole Chapter in one cycle from its confirmed Chapter Spec, with no per-Area files. It is a second lawful writer under a new rule, not an exception: /next-area still writes one Area at a time, and a Chapter is built one way, by Area or whole (Chapter Spec Build mode: whole | by-area, default whole). The deprecated [WRITE NEXT N AREAS] and [WRITE TO END OF CHAPTER] stay deprecated.

  1. Refuse a Chapter that has Area files (points to /chapter-builder or /redraft-chapter) and stop if the Chapter, any Area block or the Scene Map lacks pacing, a size target or a scene assignment.
  2. Step 0: Decision Consultation for open or deferred spec notes, then a short build plan (scenes, POV order, words per Area block and for the Chapter, any stretch) that you confirm. Auto Mode never waives it.
  3. One area-maker drafts the whole Chapter (each Area block at 55% to 60% of its size target; a stretch named in the spec may reach 72%; the Chapter total from 0.55 T to 0.72 T), then one chapter-editor edits it in one pass (seams, voice, repetition, plain language, date lines, the band), then the script measures it.
  4. Gate 1 by continuity-checker: the 24 checks over the whole Chapter (the word-band check in place of Check #10; spec conformance per Area block and the Scene Map; calendar by date segment) plus the flow review of the seams between Area blocks and the POV shifts. The staged text is printed in full; answer [CONFIRM WRITE], [REVISE CHAPTER] or [SKIP WRITE].
  5. Gate 2: the script writes the Chapter .md (with hidden <!-- AREA NN --> markers) and .docx; then the audit lane, one batched ledger update citing the Chapter reference only, and one CDL-2 block run together; the Chapter Spec is synced, every Area row set WRITTEN(P.S.N.CCC) and the spec completed in the same pass.

/next-chapter

C-6

Advance to the next Chapter (resets Area numbering within it), then write its opening Area.

  1. Invoke outline-planner to confirm every Area of the current Chapter is written and to prepare the completion of the current Chapter's spec with its final variance summary (/chapter-spec complete; nothing is written until the new spec is confirmed), and area-scorer for the closing Chapter's Chapter-Level density block (information only). The new Chapter must have an entry in its Novel-Part Spec; if the Novel-Part Spec has no further entry, the command stops before anything is written and asks which way to go: add one as a short amendment (purpose, calendar window, threads, who is on the page, key events, hook, closing beat), which gets its own [CONFIRM SPEC] and is written at once, before the Chapter Spec is built; or run /next-part, because the Novel-Part has finished; or run /part-spec revise. The Section Spec and the Novel-Part Spec above must already be in force; this command builds the Chapter Spec only.
  2. Build the next Chapter's spec via /chapter-spec build, pre-filled from that Novel-Part Spec entry — full consultation through [CONFIRM SPEC], establishing title, purpose, the Area breakdown and each Area's block (size target, pacing, scene anchors, opening and closing type, carry-over, thread) — BEFORE any Area is planned or drafted. The outgoing Chapter's completion is written on [CONFIRM SPEC], in the same step as the new spec. A departure from the Novel-Part entry is shown at that confirm (you choose to amend the plan or keep the entry as the baseline) and noted as variance on the Section Spec and the Novel-Part Spec in the same step. The Chapter window and each Area's in-story time are written as dates plus Phase Day, and the carry-in names the last dated moment of the closing Chapter (Part 41).
  3. Run /next-area with is_first_area_of_chapter=true.
Abort: do not advance a Chapter with unwritten or unresolved Area content. Never advance with the prior Chapter's spec not yet COMPLETED or the new Chapter's spec unconfirmed (Part 38) — [SKIP SPEC] at the build gate saves the drafted spec as DRAFT and stops the advance there; the new Chapter stays blocked for /next-area until [CONFIRM SPEC], and the outgoing spec is completed only on that confirmation.

C-8

  1. Check that the new Section's Title Page images exist, the Phase icon and the Section icon; if one is missing, stop and run /create-image-phase N or /create-image-section N M first. The Check #21 ledger writes land before the new Section Spec's audit, and its questions are asked apart from the Section Spec consultation, never mixed into one question call.

Once steps 1 to 3 are done, invoke continuity-checker for the session-end audit chain on the closing Section: FCIA end-of-session and ALCA Mode B together, then a Unified Audit Summary, over the Areas of the closing Section. It reports and changes nothing; a FAIL the author has not ruled on blocks the next step.

Independent reader pass, launched with the first three steps and waiting for none of them: ask which model it runs on and which three Areas of the closing Section it reads, then invoke area-scorer on that model (the model applies to this one pass only). Condense a finished Chapter's Areas into one Chapter text (50% to 60% of the Areas' characters), review it with the author, then write Chapter NNN - Name.md and .docx into the Novel-Part folder, via the authorized script exclusively. Replaces the retired /export-chapter.

  1. Confirm every Area row of the Chapter Spec is terminal and its Area file is present, and ask before replacing an existing Chapter file.
  2. The Area Maker condenses the Areas into one text staged in .claude/temp/, keeping every beat, name, planted setup and the closing beat, with --- between scenes and the date line shown once and again only when the date changes. The script measures it against the length band.
  3. The continuity-checker audits the staged text against the Chapter Spec and the Areas; the author reviews and confirms in words.
  4. On confirmation, chapter_builder.py writes the .md and .docx together into the Novel-Part folder, then the staged file is removed and the paths are reported.
Abort: do not build a Chapter with unfinished Areas, with a text outside the length band, or without the author's confirmation.

  3. Report the output path.

For the spec chain it also shows each link with its Ref and status (the active Section, Novel-Part and Chapter is the first spec in its tier that is not COMPLETED; a RETIRED spec is skipped); a chain flag naming the first link that is missing, DRAFT, AMENDED-PENDING-RECONFIRM or RETIRED (for example "no confirmed Novel-Part Spec for 1.2.3") together with the command that repairs it (/section-spec, /part-spec or /chapter-spec), or "chain in force"; the Chapter-list progress (each Chapter entry of the active Novel-Part Spec with the status of its Chapter Spec as the registry holds it, a live count of Chapters completed out of those listed, and the same count of Novel-Parts for the Section; information only, no target); and each active spec's stored coverage figure with its last-updated date (it can trail the live count, which is the one to read).

⚠ Destructive — Human-Invocation Only

Reset & Rewind Commands

Every command here carries disable-model-invocation: true — an agent can never infer or auto-trigger one of these; they only run from an explicit human slash-command invocation in the current turn, and each requires an explicit confirmation before touching anything.

/hard-reset

C-1🔒

The most destructive command in the system. Full wipe: all written Areas (the exported chapter, phase and novel files included), every spec (Section Specs, Novel-Part Specs and Chapter Specs) and the spec registry rows, all session logs, all agent memory, every density score, and every ledger's event log and Area citations (the recorded tables of the calendar ledger included; its Baseline tables stay). No ledger entity file is ever deleted — side-character files included. The ledger keeps describing the world; it stops recording the story.

  1. First ask, with a Cancel option, that you commit or copy projects/ and story-memory/; then run reset_story.py --dry-run (it writes nothing), show the counts, and confirm explicitly with a Cancel option, stating plainly what will be erased; the confirming answer names the scope in words.
  2. Run reset_story.py with no flags — the full wipe — and invoke area-scorer to return the CDL-2 density tracker to its empty template.
  3. Resolve the script's REVIEW REQUIRED report via parallel continuity-checker calls: keep the fact, drop the Area provenance.
  4. Verify zero Area references remain, then stop. It does not chain into /start-story.
reset_story.py→continuity-checkerarea-scorer

/reset-story

C-21🔒

Clears written Areas and every ledger's Area record in one pass. Unlike /hard-reset, all three kinds of spec survive with their statuses rolled back (Part 38 Rule 7.1.1; a COMPLETED spec returns to CONFIRMED) and agent memory is untouched. Canon skills, guardrails, and the canon-manifest are never touched by any reset. The calendar ledger's recorded tables and Current Position row are emptied by the script (they sit under "Events Log" headings) and its Baseline tables stay, so the story clock returns to Day One (Part 41).

  1. First ask, with a Cancel option, that you commit or copy projects/ and story-memory/; then run reset_story.py --dry-run --keep-specs --keep-agent-memory (it writes nothing), show the counts, and confirm explicitly with a Cancel option, stating that written Areas, exported files, density scores and ledger data will be reset; the confirming answer names the scope in words.
  2. Run reset_story.py --keep-specs --keep-agent-memory (the exported chapter, phase and novel files go with the Areas) and invoke area-scorer to return the CDL-2 density tracker to its empty template.
  3. Resolve the REVIEW REQUIRED report via parallel continuity-checker calls.
  4. Invoke continuity-checker for the Part 38 spec status rollback.
reset_story.py→continuity-checkerarea-scorer
