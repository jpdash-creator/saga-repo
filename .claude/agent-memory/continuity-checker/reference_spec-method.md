**Final sweep and light audit (report-only).** Read the draft whole, send progress, then re-read and compare (planner and other agents sync it mid-audit); for several drafts take a line count per file first and last and re-Grep every cited line number before reporting; token Greps per draft show whether a ruling landed in all. Scope by level: Chapter Rule 3.3.2 (a-h), Section 10.5.1 (a-k), Novel-Part 11.6.1 (a-i). Clean body is the cheapest real FAIL (`(Settled)` inside Behavioral Plan lines). A Part draft goes stale when the Section draft syncs: compare departure lists last. Read fenced paste blocks for scaffolding lines and fused list items. Re-list every skipped and deferred item. Beyond the light audit the sweep catches: Scene IDs unique in the Novel-Part (Rule 2.4.12); kept rows after a redraft carrying archived first-use text; a silent named person needs a stated tier (Tier D Named Conversational, Tier C Named Incidental); a beat object passes Rule 20.2 prongs 4 and 5 (named version is the default); header pre-fills compared word for word with the Novel-Part entry; Step 0 of `/create-chapter` asks every Open and Deferred note; an Evolution Entry touching a determinant behind Rule 29.4.4.1's floor of two is CHANGE or ADD, never RETIRE; Rule 2.3.2 catches short echoes of Part 30 wording; deep POV versus "the narration tells the reader"; a flashback opening a Chapter does not literally meet Rule 27.2.1; a Tier C viewpoint holder cannot pass POV and Head tests (no L02, L07); Threshold C-2 is asked before the file is made.

**As-built sync (Chapter Spec).** Write set: the Chapter Spec and its registry row. Area rows to `WRITTEN(ref)`; a whole-built Chapter cites the Chapter ref in Fired cells; unplanned fires are added after planned rows (Rule 3.6.1 item 8), planned wording kept in the Variance note; plan fields take the written value (smallest edit); Completion Record written in the same pass; the checker marks no setup lapsed; upward variance notes are reported, never written; Coverage cells belong to `/next-chapter`. Rule 38.14: provenance such as "(author-approved)" goes in the dated notes group at the end of Audit and Settlement Notes, never in the body. Fired-table check: `^\| (A|B) \|([^|]*\|){4}$`.

**Completed-spec retrofit (Rule 6.1.1(a)).** Status unchanged, correction of record. Grep the old words, replace them in the plan body and Completion Record, edit historical notes only where they quote page text or now say something false (add "the text of <date> read '...'"). A spec built before the 2026-10-16 amendment gets a `5.0a Cultivation Visibility` table. A cross-spec move collision becomes an Open note; edit neither spec. Calendar: re-check date line count, rows, Total Entries, weekday by formula; report "checked, no change".

**Redraft Step 2 (Rule 7.2.1).** `WRITTEN` back to `PLANNED`; names locked only by archived Areas return to `proposed`; item-6 stamps citing archived Areas revert; a variance note with command, date, prior status; kept Tier D rows get First Area, Descriptor and Current Condition `pending redraft`.

**Registering people before a draft.** Tier C: the row is the whole record in `ledger-character-side/_index.md` (Tier C row, behavioral-line paragraph, status registry, compliance, pending row, header count in three prose spots). Derive the core six with evidence and ASK only the Signature (Rule 39.45.1.4); with no author answer nothing is `[ASKED]`; `OPEN-AREA` when the first Area can set it, `OPEN-AUTHOR` when only the author can (address forms, realm stage, Threshold C-2). A Chapter Spec is a plan, not canon (cite "from: plan, Area NN anchor N"; the ledger beats the plan). A Tier C side villain is filed in `ledger-character-villain/_index.md` with one pointer row in the side index. After the author accepts a digest values stay `[DERIVED]`, strip "provisional", keep pending rows only for `OPEN-AUTHOR` fields. Do not pick catalog codes from thin page evidence: add a page-record paragraph and ask for a digest. Tier B partial: the core six Layers (L01, L03, L08, L10, L29, L34) one `[DERIVED]` line each from a named beat, other dimensions listed by mnemonic as OPEN-AREA or OPEN-AUTHOR so the 291 tally holds, only the plan's fired Signature. A "Tier B side villain" has no slot (Rule 18.6.3.2: Tier C or D only; Tier A and B villains are author-mapped full files). Address forms are never coined. Tier C is exempt from Rule 29.4.4.1 but stays under 29.4.4.3 and 29.4.4.4.

**Tier B after the author's interview (Rule 39.45.1.4), written pre-draft.** The author's picks are `[ASKED]`; the planner's digest values are written `[DERIVED]`, each with cited evidence, the digest's alternatives named and a "flagged, Check #21 expected at the first Area that shows him" mark; an immutable is always the author's, so "none" is flagged. L34 follows the Kellan pattern: CLASS and END `[ASKED]` when offered inside the picked option, STATUS and KNOWN `[DERIVED]` when they are the interview's stated defaults. The Signature table keeps five columns with the four L34 codes inside the Origin cell. Two picked codes in one dimension are lawful for a Tier B person (the one-code limit is the Tier D code's, Rule 39.3.5.3): one bullet line carries both, the dimension counts once in the 291 tally, and the Signature count counts both. Recompute the tally by Layer and re-add to 291; a registered costly behavior turns Owed Beats into a 3-cell table; Section 12 gets an italic note under the table (no row, no drift); Section 1 voice lines name the scope and, for PSM-7, the Rule 29.4.4.1a (e) state. Index touch-points for the person: the Total Entries prose, the Tier B row (Status and Stoppers cells), the annotation, the pending row (interview items out, flagged lines and "Check #21 expected" kept), the status registry row, the "not one of the fourteen" paragraph (leave the fourteen and 22 counts alone), the compliance row. One Edit per file per message (two parallel Edits on one file persisted but are a race: re-Grep both). An amended anchor set in the Chapter Spec reaches the Tier C behavioral line, the pending row and the status registry row together: Grep the old code over the index and keep the old set out of the new text.

**Light-audit checks that are easy to miss (Chapter Spec with children, moves and a new institution).** Grep the draft for `ANCHOR`: any person aged 12 to 16 (YC-2) or under 12 (YC-1) needs three registered `L30-ANCHOR` behaviors and one rendered per Area (Rule 39.34.1.1, element 20-11), Tier C and B included. Manual titles are plain italic, article outside (Rule 42.13.1.1, Rule 20.8.2); a manual-borne move registers as `Lineage or school technique` (Part 6 Rule 6.5.3). Read each move's row in `ledger-manuals/moves/*/` and the manual's `min_realm` and the institution in `kingdoms/*.csv`. Grep the Section and Novel-Part Specs for claim words ("only", "the one", "no ... on the page") and table Note cells, and compare with the plan; a missed Variance is a FAIL. Quote the ledger's own open-items numbering, never the planner's. Read the previous Chapter's Completion Record seeds and the written text for follow-ups the plan must pick up (a promised later delivery, a forecast's exact words). A sibling signature's definition can bar a planned beat (a "stops only when alarmed" signature and a stop planned at a calm moment). Scan new names whole-word and case-insensitive over the repo, then read stem echoes against the side index by consonant skeleton (two first names with the same consonants and different vowels are an echo). The planner's draft may be copied to `.claude/temp/` while you read: `Glob` does not list `.claude`, use `Grep -l`; compare copies by line count and a few distinctive lines, and finish on the delivered copy. A planned anchor must fit the catalog gloss and the ledger's own reconciliation note that separates it from a Signature (a question that targets a hedge in the line before it is the Signature, not the naive-question anchor), and its registered or proposed set; a child "only named" owes none, but "glimpsed" is still present. A new title or class of office-holders is traced by grepping every ledger for "below the X", "only X", "exactly one" and for the mirrored address rows, and is read against registered concepts that may already name the class (a delegation model, a "master" office) and against any sole-authority line.
