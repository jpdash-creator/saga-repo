**Write order (Part 38 Rules 9.4.4, 9.4.5; precedent logs `session-log/2026-10-20-chapter-006-spec-confirm-parent-amendments.md` and `2026-10-20-chapter-007-spec-confirm.md`).** (1) Section Spec header lines 5 to 8, the changed block lines, then one new block 12 group "Revision of <date> (Chapter NNN ...)" (amendment log, whole-group trigger, one Variance note per departure with the original beside the new, Deferred pointers, Settled pointer). (2) Novel-Part Spec the same way (block 11). (3) The new Chapter Spec file, then (4) the outgoing Chapter's completion pieces, (5) registry rows (Section and Novel-Part Coverage refreshed, new Chapter row), (6) session log. The registry `_index.md` is the planner's to edit at this step; ledgers are not.

**Light or substantial.** Part 38 Rules 9.4.2, 11.4.2 and 11.7.2: a change inside one Novel-Part entry (plus a cut-plan cell of the same Chapter) that leaves the Novel-Part's own purpose, calendar window, reveals owed and closing state as they were is LIGHT: version bump, log line, status stays CONFIRMED, no re-confirm, no audit. A Chapter-list guide line in the Section Spec is light (Rule 10.6.2). Chapter 006 was substantial only because it also changed block-level lines and reveals owed. Light amendments still bump the version (v1.3, v1.5, v1.7 precedents); variance-only notes do not.

**Draft pitfalls found 2026-10-20.** (1) The draft's "proposed amended wording" omitted two items (row 13, the Nine Halls) from Threads out that the header and its own Threads Variance note carried: compare the proposal field by field with the section 1 header before writing the entry, and say in the notes which wording was used. (2) A new Chapter's draft carries "DRAFT", "confirm still to come" and "nothing is written" sentences in the header, the first Audit note and the section 7 intro: correct each in place with the old reading quoted once. (3) Settled-by-default and other planner defaults get no author status from a bare [CONFIRM SPEC]; add an Audit note saying the relay carried no change (Rule 4.1.2) and invent no answers. (4) The Novel-Part Spec header stamp may carry stale "no file yet" phrases: report, do not edit.

**Completion pieces of the outgoing Chapter (Chapter 004 and 005 precedents).** Header line "New named things" gets a "By Area of first appearance" list (verify each name, Kind, move, bell, ford and pit against the written `.md`; Area markers are `<!-- AREA NN -->` lines); the section 6 "Completion answers" line is replaced by the relayed answers; the digest gets an "Accepted variances by Area ... Accepted sameness patterns" tail; section 7 gets a last group "Completion write at /next-chapter (Ref: ...), <date>" (Settled answers, Settled lapses, Audit on the refresh, Audit on the Coverage cells); older notes that read "not yet asked" keep their words and get a "Corrected <date>" suffix. Status and version stay (COMPLETED, v1.0); the registry row needs no edit when its Last Updated already equals the date.

**Copying a long draft with no copy tool.** Write chunk 1 ending in a sentinel line, Edit `last-line-of-chunk + "\n" + sentinel` into the next chunk plus the sentinel; the last Edit drops the sentinel and leaves a doubled newline at EOF (the file then counts one line more than the draft: remove it with an Edit). Verify: line counts and heading line numbers after every chunk; then Grep with `path: .claude`, `glob: **/chapter-NNN-spec*.md` and `output_mode: count` to get the draft's and the copy's counts in ONE call (lines with `^- \*\*`, `^\|`, `^#{2,4} `, `\*\*\*`, `B39-L`, names, figures, end-of-line phrases ending in `$`). Windows: `-o` with `.{0,200}(kw1|kw2|...).{0,200}` prints the same window from both files; a match over about 500 characters prints "[Omitted long matching line]", so keep windows under 450. Sampling 50+ windows over the long lines found no error in the 2026-10-20 copy. Still ask the orchestrator for `git diff --no-index` and list the intended differences.
