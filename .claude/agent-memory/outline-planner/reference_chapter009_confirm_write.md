Facts and traps from the one-step write of 2026-10-22 (author's [CONFIRM SPEC] for Chapter Spec 1.1.1.009). Chapter facts live in the specs; these are only the working lessons. See also [[reference-confirm-write-step]].

- **Order the coordinator set.** (1) Part 30 and Part 35 edits in place (no line added) and the session-log file named in the staged stub; (2) Section Spec edits, its new block 12 group, registry version cell; (3) Novel-Part Spec the same, block 11 group; (4) new Chapter Spec and its registry row; (5) outgoing Chapter completion pieces, then the Coverage cells of the Section and Novel-Part rows. The Coverage flip comes last because it claims the completion write; the version cells go with their spec.
- **Edit tool is the re-verification.** An Edit fails when the OLD string is missing or not unique, so a clean run of 27 + 22 single-line Edits plus a 15-line block replace (the entry) proved every OLD matched once. CRLF files (Part 30, Section Spec) kept CRLF on single-line edits and on a 17-line append (555 of 555 lines, 886 of 886).
- **Staged drafts still carry pre-confirm wording.** The staged Chapter Spec had DRAFT in the Spec Status, Spec Version, Last Sync and Light Continuity Audit lines, "staged beside this spec" in the Built-against stamp and R10, "nothing is written ... DRAFT until" in the section 7 intro, "not yet run ... still to come" in the first Audit note, O18 ("until the author confirms them"), the Variance heading and the Parents note. Fix each in place with "Corrected at the write step ..., a correction of record" (mirror chapter-008-spec lines 4, 734, 737, 858, 890) and add one last Audit note for the write step (the copy is then staged lines + 1). The staged files held NO light-audit verdict: write a placeholder that quotes the staged reading and leave the date and verdict to the orchestrator; flag it. The parents' staged header sentence "light audit ... runs before that confirm" was written as staged. A staged pointer such as "(staged beside this list)" in a parent group is a dangling pointer after the write: reword it.
- **Sentinel copy numbers.** 1,095 lines (97 lines of 600+ characters, 6 of 3,000+) in 16 chunks of 40 to 65 lines. The sentinel's line number equals the next staged line to read; a chunk starts with a bare newline when the staged line at the sentinel is blank (it worked); the last Edit ends with no newline. Passed: line count (staged + 1), `^- \*\*` (+1), `^\|`, `^ +\|`, `^#{1,4} `, `^  - `, `\*\*\*`, `B39-L` equal on both files; two `-o` window sweeps with the same pattern on both files identical; sentinel count over `.claude` 0; no contraction; unwrapped item and move names 0.
- **Completion write.** Chapter 008 edits E1 to E9 all matched at the staged lines (57, 640, 672, 680, 718, 734, 937); the append added 7 lines and 6 non-empty lines; `## 6` and `## 7` did not move; "not yet asked" stays only inside the quoted history of E6.
- **Session-log file for a Canon Amendment.** The stub says the orchestrator completes it at the reconciliation; when told to write it, give a Files-changed table of what was really done and say that the CCIA search is not run by the write step.
