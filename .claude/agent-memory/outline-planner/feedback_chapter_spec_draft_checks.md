**Recount paired fight Areas.** When one fight runs across two Area blocks, recompute the dead and wounded of each side after drafting both Engagement Ledgers: the first draft of Chapter 005 gave different casualty totals in the Purpose, the table and the Price line. Positions are `4 x (Level - 1) + 0/1/2/3` (Low, Mid, High, Peak); recompute every gap range from the band ends, and make sure the group counts add up (a company equals its anchor, leaders and ranks).

**Why:** Part 44 Check #23 compares the draft with the spec's ledger; a count that differs between two rows is a finding the author sees.

**How to apply:** after the last fight block is written, Grep each side's count words ("five", "two", "seven left") and read the table rows against the Price paid line.

**Open the file before saying what a ledger "reads".** A location file may have a Collective Behavior Code stub (`highgale`) or no block at all (`aerie-palace`; its code is recorded as pending in `aeries` Section 11.5). Say which, with the file named, in the Behavioral Plan and in the Open note.

**Why:** a wrong claim about a ledger block turns a blocking item into a false statement.

**Scene seams in a multi-viewpoint scene.** Two Area blocks of one scene need a join state that both sides can honour: if a clock moves (a pause, a skip), the Area that keeps the earlier clock must not claim an event that falls after the skip. Check the anchors' order against the Planned time skips line.

**Ledger beats the author's ruling only on established facts.** When the author supersedes ledger text (an address system, a working name), write the ruling in the spec as Settled, name every carrier file by name only in an Open note for the Gate 2 ledger step, and do not edit the ledger.

**Revising a draft after rulings arrive.** When the author overrides planner picks after the hand-off, withdraw each contradicted Skipped pick, turn the Open notes the rulings close into Settled notes (keep the first answer's source and say the planner's pick is withdrawn), then Grep the old noun and its topic words (rank word, survivor, "alive", the omitted fact) across every Area field, the Scene Map, the visibility table and sections 3 and 7. Re-check every "(section 7, Open)" pointer afterwards: a pointer to a note that was removed or never existed is the usual leftover.

**Read the new registration before editing around it.** A ledger registered the same day (a villain's Sections 1, 4 and 11) carried a belief ("nothing is left on the road"), a voice ruling and a kill state that changed three plan lines. Plan traces and clues so they fit the registered belief (name what the clearing could not remove), keep ledger status tags such as `[N-A]` out of the spec body (write "marked not applicable"), and split an anchor into marked beats when it would stack three registered dimensions.

**Late tier and stage rulings.** When the author re-tiers named people (seven Gale people to Tier D) or leaves a field unset (the stage of a Level), Grep "Tier C", "registered before drafting", "blocking" and the old registration phrases across the header, every Behavioral Plan, Debuts, the visibility table and the Open, Audit and Variance notes. Keep the first answer's note, add the Settled replacement beside it, and quote the entry's original words in the Variance note. An unset stage is a step range from the band ends (a Level spans positions 4(L-1) to 4(L-1)+3), never a stage by implication. A coordinator's position numbers may be 1-based (21 to 24 for Level 6); the gaps agree, so state the rule's numbers and flag the difference once. Cite no ledger line the author has left open in a Behavioral Plan, even when the ledger file still shows it.

**Post-confirm light annotation and parent variance notes.** When the coordinator brings the author's confirm and asks for the checker's record notes as a light annotation (section 7 plus a few named body lines) and for variance notes on the parents: write Section Spec first, then Novel-Part Spec, then the Chapter Spec, so the Chapter Spec never claims a note that is not there; match the parents' own group format (a group heading, a trigger note, one note per departure with date, trigger, original beside new, the author's answer); after removing Open notes, grep "(section 7, Open)", "(blocking)" and "not yet given" for dangling pointers and unfilled answers; fix a stale status line in place with a "corrected, a correction of record" label and quote the old reading once. A "none, by the author's ruling" status is true only for what the author ruled: Part 39 lets a Behavioral Plan cite a location code as Registered or none by the author's ruling, so a planner's-reading none goes in a Skipped note and is flagged to the coordinator as a possible Gate 1 reading. Leave the header alone when the brief limits the edit to section 7 and named lines, and report its stale lines (status tail, the N1 to N8 count) instead.

**Why:** the Chapter 005 annotation of 2026-10-18 touched three files in one run and each of these slips would have left a false or dangling statement in a confirmed spec.

**How to apply:** at any post-confirm annotation, before the hand-off, run the three greps above and list the untouched stale lines in the report.

**Tooling.** No Bash: compress CSV lookups with Grep `-o` and a narrowed regex (id, manual, seq, name, type, unlock), and read long ledger files in slices of about 90 to 120 lines. A broad case-insensitive name scan returns noise from short surnames; scan whole words (`\b`) and keep short names in a separate pass.

**Edit-tool traps in a cleanup lane (2026-10-18, spec clean-up after a light audit).** (1) An Edit with an empty `new_string` that removes text at the end of a line also removes that line's break, so the blank line before the next heading is lost (it happened on the Section Spec carry-in line); keep the preceding words in `old_string` and `new_string`, and Grep the neighbour lines afterwards. (2) `section-1-spec.md` is CRLF (Grep `\r$` count equals the line count) while the Part Spec and Chapter Specs are LF; the Edit tool keeps CRLF on inserted lines, so single-line edits and end-of-file appends are safe, and a count of `^` before and after shows a lost or gained line. (3) The coordinator's line numbers shift after the first edit and may come from another snapshot: re-locate each target by content (Grep `-o` with a 100-character window), count repeats, then `replace_all` for the identical Backfilled strings. (4) Removing paired code-fence lines: put the heading line in `old_string` to make it unique, and turn a closing fence that sits before a bullet into a blank line.

**Why:** the clean-up touched five spec files in one run; the lost blank line was caught only by comparing the `##` line numbers with the first read.

**How to apply:** after the first batch of edits, Grep the `^## ` and group-heading line numbers against the first read, and use the same Grep to confirm the final line count.

**Writing section 7 of a long whole-mode draft (Chapter 006, 2026-10-19).** (1) Compute each Engagement Ledger gap cell from the fighters present in that row's Area only: a union range copied across Areas put a Crag Buck's 62 into an Area where the bucks were held back (fixed: "20 to 54", "44 to 66"); redo the Audit note from the corrected cells. (2) Keep the body free of "Section 7, Settled/Open/Skipped" pointers and of provenance clauses ("the author's rulings of ...:"): the Continuity Checker ruled them clean-body blockers on the Chapter 006 draft (2026-10-19), so the notes point to the body item and never the reverse; Grep `[Ss]ection 7` over the body before the hand-off, and write consultation numbers ("Q9") as the ruling in words, since the proposal file is temporary. (3) Open versus Skipped: a planner's reading of an author phrase ("no child hurt", "land still unset", "breach at the forest edge") is a Skipped note and a residual question for the report; Open holds blocking registrations, ledger-side writes and flags the author must rule. (4) Name scans: include the optional space and hyphen forms; hits in `ledger-manuals/names.json` and `_rename-map/*.csv` are retired old names (read `old_name,new_name` first), so they are echoes and not clashes. (5) Read what a hero ledger already holds before writing the Named-Move Open notes: the Section 3 ruling note and the Section 14 pending pointer of a Canon Amendment, cells the amendment left alone (`B39-L25-MOVE-01` reads not applicable in `hercules`; the Wind reservation sits in `bison` Section 3), and `character-kits.csv` rows (the heroes hold only their `PER-` manuals, so kit rows are owed and E3 link codes need Practiced or better). (6) Part 39 Rule 39.3.5.6 item 2: Tier D persons who act or decide are flagged to the author and not coded before the ruling, even when the author has said "all Tier D"; keep one Open flag. (7) Whole-build wording: "before Area N is drafted" reads "before the Chapter is drafted", and a ledger status that the plan cites as "None, by the author's ruling" (a collective code stub) goes on the pre-draft list, not the Gate 2 list. (8) A Tier D person who debuts in a viewpoint whose sense reads no one needs a short identification as the Cultivation Visibility route (name the table row); an Area that continues a scene opens "continues directly", with "repeat on purpose" when consecutive Areas share the type (Chapter Spec 003 precedent). (9) Partial-word name scans (a Kind word inside move and manual titles; first names beside registered people) are what the checker runs; run them too and list echoes as one Open note without picking. (10) Deleting whole note lines: never use an empty `new_string` (it eats the line break and fuses neighbouring notes, which happened to three Open notes on 2026-10-19); put the next line's opening words in both `old_string` and `new_string`, and send line-deleting Edits one per message. (11) When the author rules every departure "amend" (2026-10-19), turn each Variance answer into a Settled note, change every "Recommended: leave baseline" to amend, and append a clearly marked "Parent amendment worksheet" after section 7 (working material, deleted at the confirm): OLD and NEW per parent line, locating by opening words, plus NOTES to append to each parent and the status/version it will carry; history notes (Audit or Settled of earlier dates) get an appended note and are never edited.

**Why:** each slip would have left a wrong number, a dangling pointer or a false clash in a spec the author reads at the confirm.

**How to apply:** run (1) and (2) as the last two checks before the hand-off, after the sentinel is dropped.

**Correction of record after the ledger catches up (Chapter 006, 2026-10-20, post-confirm, status stays CONFIRMED v1.0).** (1) Check each "now written" claim in the file before wording it: villain files (Section 11 counts, slots, waits, AL answers in the header), `character-kits.csv` (Grep `^(HRC|BSN),` for the new rows), `hercules` grant notes (Sections 3, 11, 14) and `bison` (Section 3 SUPERSEDED note); one claim that is not in a file stays "owed". (2) The coordinator's line numbers come from another snapshot: re-locate every target by content (Grep -o, 100-character window), and Grep the whole spec for the stale words ("unregistered", "interview", "blocking item", "no file yet", "written now") because some carriers are not on the brief's list (Section 3 line for the Veiled Party; the same "no file yet" phrase sits in the Novel-Part Spec header, which the brief did not name: report it, do not edit). (3) Pattern: body lines get plain corrected text with no tag; Open and Audit notes get a "corrected <date>" suffix; Settled notes stay as history (append a dated clause only where the brief asks); new Audit notes go at the end of the Audit group, one per correction group, quoting the old reading once. (4) Two identical table rows in different Areas: use the following line as context for the first Edit, then the second is unique. (5) The ledger's own dates can differ from the spec's (kit rows say the Expert ruling is 2026-10-20, the Settled note says 2026-10-19): keep both and say so in the Audit note.

**Why:** the last fixes-only check found pending-work statements that were already done; a half-fixed carrier leaves the spec contradicting itself.

**How to apply:** at any post-confirm ledger catch-up, run the stale-word Grep before and after the edits and compare section 7 heading line numbers.

**Re-audit lessons (Chapter 006, 2026-10-20).** (1) Ledgers move between rounds: before a spec says a ledger entry is "owed", Glob and Read the ledger again (the six Kind files, the Reserved row, the artifact line, the forest Code Status and a castle stub had all been written the day before) and say "written (status PLANNED)" plus what the Gate 2 still confirms; keep the pointer note in the Audit group, not in Open. (2) Parent block numbers: Section Spec notes are block 12 (block 10 is Standing Exclusions, 11 the Completion Record); Novel-Part Spec notes are block 11 (read the `^## ` headings of both files before writing worksheet NOTE lines). (3) Rule 9.4.5 case 1: a Chapter's departures from its Novel-Part entry leave a note on the Novel-Part Spec and on the Section Spec, so the Section Spec's own worksheet note must name them. (4) Every parent line a worksheet edits needs a matching Variance clause with the original beside it (check Purpose, Place, Reader knowledge, Row 13, Technology, Closing state lines, not only the headline ones). (5) The author-held Brackenhold card: quote the author's own words only ("working on, and influencing, the king of Brackenhold"); never add "does what he is leaned on to do", "in the same way" or "reaches for". (6) A level for a returning speaker from an earlier Chapter still needs a Chapter route in Hercules's sense (Check #8-V). (7) A relay-dated note (author words that arrive the next day) carries the relay date, and the section 7 intro says so. (8) Check #17(a) names the Narrative-Significance line; an author waiver is a Settled note plus a Names note, and the body says "the author has waived Check #17(a)" without a pointer tag.
