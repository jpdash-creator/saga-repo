> **Purpose:** This folder contains ledger files for Tier A (deep) and Tier B side characters per Part 19's four-tier Depth Spectrum (A/B/C/D). Tier A and Tier B characters receive full individual ledger files using the thirteen-section Character Ledger Template, each with a registry row in this _index.md. Tier C characters are tracked as entries in this _index.md; each Tier D person is one registry row.

> **Tier Definitions (Per Part 19 Area 1.2):**
> - **Tier A:** Deep-depth side characters with substantial independent arcs, explicit psychological profiles, and narrative functions that can generate CSS-5+ events. Require full ledger files.
> - **Tier B:** Moderate-depth characters with defined roles but limited arc scope. Hold their own full ledger file (the Ledger Type reads Tier B); tracked here by a registry row that points at the file (name, function, current status, key relationships).
> - **Tier C:** Functional/background characters with minimal narrative complexity. Tracked in the index with single-line entries.
>
> **Tier D — the fourth row of the Part 19 Area 1.2 spectrum:**
> - **Tier D — Named Conversational:** one registry row in this index and nothing else, registered at Gate 2. The rules of the tier (what it carries and does not carry, speaking, promotion, negotiable canon) are Part 19 Rules 19.1.2.3 to 19.1.2.7; the row layout is Part 37 Area 2.11; the picked code is Part 39 Section 3.5. See **"Tier D Named Conversational Characters — Registry"** below.

> **Critical Rules:**
> - Mentor Death (Part 19 Rule 19.2.1.1) — a permanent event — requires immediate ledger update and [CONSEQUENCE AUDIT] C-18.
> - No unresolved Tier A character threads at arc close (Part 19 Rule 19.9.3.2).
> - CS%/TS% values for Tier A characters are tracked in their full ledger file Section 2 and summarized in the Tier A registry table here. Tier B characters include CS%/TS% in their file Section 2. All values per Part 31 Area 21.4.

> **Update Protocol:** The Pre-Write Ledger Check (`guardrails/ledger/guardrail-ledger-update-law.md`) reads the Tier A and Tier B files, the Tier C lines and the Tier D rows of every character in the Area, by name, before any prose where they appear. The Post-Write Ledger Update (`guardrails/ledger/guardrail-ledger-update-law.md`) updates entries after any narrative function event, death, status shift, or significant relationship change.

> **Marker Legend:** These markers appear in the entries of this ledger. Open cells otherwise carry `OPEN-AREA` or `OPEN-AUTHOR` (Part 37 Area 5).
> - `[ASKED]`: the author chose this value.
> - `[DERIVED]`: the drafter inferred this value from cited evidence and the author reviewed it in the digest without overriding it (Part 39 Rule 39.3.3.1); it is pending only when the entry also says flagged for author confirmation.
> - `[AUTHOR-PENDING]`: a question about this value has been raised and is not yet answered.
> - `[MARKED SLOT]`: a slot left empty on purpose until the author rules.
> - "flag, do not invent": when a scene needs the value, the prose may establish one small fact at a time under Part 28 Area 17, logged in this ledger and offered to the author as a draft value at the next Section close. A name or a major entity (Part 28 Area 20.4) goes to the author first, through the Decision Consultation Gate.
