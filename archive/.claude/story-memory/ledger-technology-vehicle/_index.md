> **Purpose:** This folder tracks named canonical vehicles that appear in the novel — vessels, craft, and vehicle systems of narrative significance that exceed individual character ownership scope, or that are named and recurrent enough to warrant dedicated tracking. Character-owned personal vehicles are also recorded in Character Ledger Section 8; this folder holds the vehicle-level record for named vessels and fleets.

> **Entry Categories:**
> - **Named Vessel Files:** Individual files for named vehicles (typically SC-III+ or narratively significant smaller craft) — tracks vehicle tier, Scale Class (SC), vehicle type, configuration codes, crew, armament (cross-referenced with ledger-technology-weapon), operational status, and history.
> - **Fleet Registry Files:** For faction fleets of narrative significance — tracks fleet composition by SC class, commanding faction, current deployment, and operational status.

> **Update Protocol:** Per Part 1 Area 6, the Pre-Write Ledger Check reads vehicle state before any prose where a named vehicle's capabilities or availability are plot-relevant. Vehicle acquisition, loss, significant modification, destruction, and change of commanding officer trigger mandatory Post-Write Ledger Update. Character Ledger Section 8 and this folder are both updated for any state change involving a character's named vessel.

> **Command Interface:** [STATUS] (C-13) can report key vehicle asset states from this ledger.

> **CS%/TS% Tracking:** CS% (Cultivation Synergy %) and TS% (Technology Synergy %) for Named Vehicles are Base Information (B) at ledger entry creation per Part 31 Area 21.12, with Living Information (L) updates triggered by CHV class upgrade, soul-interface formation, or major structural modification. CS% is governed by CHV Class (CHV-A through CHV-E) and formation array drive density; TS% is governed by Scale Class (SC-I through SC-X) and technology tier of manufactured systems. The registry table includes CS%/TS% and CHV Class columns for quick reference. Synergy Dawncraft vehicles (Model C/D pilot-integrated) typically carry CS% = 72%–88% and TS% = 68%–85%.

## Part 28 Area 17 — Lore Section Schema (Vehicle Domain)

**Added:** 2026-04-19 (formal Canon amendment — schema expansion pass).
**Governing Law:** Part 28 Area 17 (Lore Creation Law). **Audit Hook:** Part 1 Area 8.13 ALCA dimension AL-10 (Lore Completeness Alignment).

**Mandate:** Every named vessel, fleet, and narratively significant vehicle must carry a dedicated **Section 5 — Lore (Part 28 Area 17)** block populated to the Breadth-and-Depth Standard.

**Required Axes (Minimum Lore Fields per Part 28 Area 17.2 — Vehicle):**

1. **Designer** — who engineered it; named lead designer or design house; governing Part 32 CT-Band tier.
2. **Commission Date** — when built; commissioning authority; named commissioning event if notable.
3. **Operator Lineage** — who has piloted/owned it; named captains and crew where known.
4. **Distinguishing Features** — physical and functional signature; named hull paint, named call-sign, named quirks of handling, named modifications.
5. **Known Missions** — events it has participated in; named battles, named expeditions, named transport runs.
6. **Reputation and Mythology** — what the vessel is known for in-world; named folk reputation; songs, warnings, or rumors attached to it.

**Depth Test (Part 28 Area 17.3):** "Can I write a 1800%-immersion scene aboard or about this vehicle using only what is in the ledger?" If yes, depth is satisfied.

**Silent Overwrite Prohibition (Part 28 Area 17.5):** Once vehicle lore is recorded, it is fixed under the Establishment Threshold.
