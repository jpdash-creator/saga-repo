Reference & Process Map

How the Starward Saga agents and commands fit together

Two layers work together on this project. 4 agents under .claude/agents/ do the actual thinking — planning, drafting, auditing, scoring. 33 slash commands under .claude/commands/ are the orchestration layer: each one is a fixed sequence that invokes agents (and, in a few cases, authorized Python scripts) in a specific order, so the same operation always happens the same way. This page maps every one of them and how they chain together.

Almost every command that touches prose funnels through /next-prose — the Two-Gate Pipeline in the Core Pipeline section below. The fastest way to understand this whole system is to read that diagram first, then treat every other command as either feeding into it, auditing around it, or reporting on it.

How to read a card

Session Control — pauses execution mid-sequence.

Layer 1 — The Specialists

Agents

Every command ultimately delegates real judgment to one of these four. None of them invoke each other directly — the invoking command always orchestrates the hand-offs, in the fixed order described in each command's card further down.

outline-planner AGENT
model: opus effort: xhigh tools: Read · Write · Grep · Glob

Decides what happens next — at whatever granularity is asked for (prose unit, Area, Chapter, Novel-Part, Section, or Phase) — before Prose Maker drafts anything. This is genuine ambiguity-resolution work (competing valid directions, pacing tradeoffs, cross-Part dependencies), which is why it runs at xhigh effort.

Reads before planning
  • Guardrails index, authority-tier & domain-ownership, locked-vs-negotiable canon
  • Current position on disk (never a remembered position) + Part 30 / Part 2 skills
  • Relevant story-memory/ledger-*/ entries for every entity in scope
Hard boundaries
  • Respects the Phase 1 8-Section lock and Locked Canon — won't plan around it
  • Decides what scene happens next, never how a fight resolves (that's audit-time territory)
  • Surfaces canon-structural tradeoffs instead of silently picking a direction
Hands the confirmed plan to prose-maker. Does not draft, audit, or update ledgers itself.
prose-maker AGENT
model: opus effort: high tools: Read · Write · Grep · Glob

Writes the actual prose of the novel — exactly one prose unit per invocation, never more. Drafts from the Outline Planner's confirmed plan; never decides structure and never audits its own output.

Reads before drafting
  • Locked-vs-negotiable canon, prohibited creative acts, Tier-0 narrative quality
  • Pre-Write Ledger Check on every entity that will appear
  • The exact ssc-* skills relevant to this unit's content, via skill-index.json
Hard boundaries
  • Must be a living scene, not a technically-correct lecture (Part 36)
  • Content-density-aware while drafting, not just scored after the fact (Part 35)
  • Never contradicts Locked Canon or anything already accepted in prior prose
Hands the draft to continuity-checker for Gate 1. Does not write the final file itself — that happens via authorized scripts at Gate 2.
continuity-checker AGENT
model: sonnet effort: xhigh tools: Read · Write · Edit · Grep · Glob

The audit and ledger-update authority. Cross-references canon skills, story-memory ledgers, and written prose every time, then verifies. Only agent with Edit — it's the sole writer of ledger state changes.

Forced-read discipline (non-negotiable)
  • Physically re-reads canon-manifest/*.json from disk — never from memory — at Pre-Prose Read, Gate 1, and Gate 2
What it runs
  • Gate 1 — Post-Draft 16-check audit; a single FAIL blocks [CONFIRM WRITE]
  • Gate 2 — Post-Write re-verify + Completeness Indicator + Tier Scope Brackets
  • CCIA — governance/structure integrity · FCIA — 16-dimension narrative audit · ALCA — ledger/rule correctness
  • Ledger updates — Pre-Write Check + Post-Write Update against story-memory/ledger-*/
Never resolves a conflict itself — surfaces it via AskUserQuestion. Logs every outcome to session-log/ (but never reads that log back as a decision input).
prose-scorer AGENT
model: sonnet effort: high tools: Read · Write · Grep · Glob

Scores prose units against the CDL-2 Content Density rubric — 10 categories, 4 Anchor Floor categories, and a running Section aggregate. Deliberately runs at high rather than xhigh: consistency across many scoring passes matters more than extra depth on any one pass.

Scores
  • Combat · Named Moves & Techniques · Cultivation Growth · Technology · Lore & World-Building
  • Dialogue & Social · Information & Intrigue · Consequence & Psychology · Travel & Discovery · Political & Faction
★ Anchor Floors (≥20% per Section, flagged specifically)
  • Combat · Cultivation Growth · Dialogue & Social · Lore & World-Building
Reports plainly, including under-target categories — never smooths over a persistent shortfall. CDL-2 only; never references the retired CDL-1 framework.

Layer 2 — The Workflow

The Core Two-Gate Pipeline — /next-prose

This is the workhorse every prose-producing command eventually calls. It's the exact sequence /next-prose runs, and what every Structural Advance command and Revision command re-enters. Nothing gets written to disk without passing Gate 1 clean and receiving an explicit human confirm.

Loop-backs on the left re-enter at prose-maker — a Gate 1 FAIL or a [REVISE PROSE] never skips straight back to drafting without going through outline confirmation again if the plan itself was the problem.

Feeds Into the Pipeline

Structural Advance Commands

Each of these confirms the current structural unit is complete via outline-planner, establishes what the next one covers, then calls /next-prose for its opening prose unit with the right is_first_prose_of_* flags set. They nest: a new Phase's opening prose is simultaneously its first Section's, Novel-Part's, Chapter's, and Area's opening prose.

/next-areaC-5

Advance to the next narrative Area within the current Chapter, then write its opening prose unit. ("Area" = Part 2's six-tier structural unit — Phase → Section → Novel-Part → Chapter → Area → Prose — distinct from a canon-law ssc-* Area.)

  1. Invoke outline-planner to confirm the current Area's beats are all covered and establish what the new Area covers.
  2. Run /next-prose with is_first_prose_of_area=true.
Abort: if the current Area's beats aren't actually finished, surface that rather than advancing early.
outline-planner→/next-prose
/next-chapterC-6

Advance to the next Chapter (resets Area/Prose numbering within it), then write its opening prose unit.

  1. Invoke outline-planner to confirm all Areas of the current Chapter are complete; establish the next Chapter's title/purpose/opening beat.
  2. Run /next-prose with is_first_prose_of_chapter=true and is_first_prose_of_area=true.
Abort: do not advance a Chapter with open/unresolved Area content.
outline-planner→/next-prose
/next-partC-7

Advance to the next Novel-Part (resets Chapter numbering within it). ("Novel-Part" = Part 2's structural unit, distinct from a canon-law Part like Part 3 or Part 22.)

  1. Invoke outline-planner to confirm the current Novel-Part's Chapters are complete; establish the next Novel-Part's arc contribution per ssc-narration-p30-*.
  2. Run /next-prose with is_first_prose_of_chapter=true, is_first_prose_of_area=true, and the new novel_part_name.
Abort: do not advance if current Novel-Part's arc threads are left unresolved without cause.
outline-planner→/next-prose
/next-sectionC-8

Advance to the next Section — one of Phase 1's 8 locked Sections — with title-page handling.

  1. Invoke outline-planner to confirm the current Section's Novel-Parts/Chapters are complete; establish the next Section's thematic contribution.
  2. Invoke prose-scorer to finalize the closing Section's CDL-2 running aggregate first.
  3. Run /next-prose with is_first_prose_of_section/chapter/area=true.
Abort: if the 8-Section lock would be exceeded, or the closing Section has an unresolved Anchor Floor failure.
outline-plannerprose-scorer→/next-prose
/next-phase C-9🔒 human-only

Advance to the next Phase of the series. Rare — Phase 1 alone is 8 Sections; only invoke once Phase 1 is genuinely complete. Total phase count is explicitly "TBD" per canon.

  1. Confirm all 8 Sections of the current Phase are complete and audited clean (session-end FCIA + ALCA Mode B already run).
  2. Invoke outline-planner to establish the new Phase's premise and arc framework.
  3. Invoke /create-image-phase for the new Phase's icon.
  4. Run /next-prose with all four is_first_prose_of_* flags set true.
Abort: never advance a Phase with an incomplete or unaudited prior Section.

Re-Enters the Pipeline

Revision & Redraft Commands

A revision is never exempt from the audit pipeline just because the unit was previously accepted — each of these re-runs the full Gate 1 → Gate 2 cycle rather than doing a diff-only check.

/revise-proseC-28
arg: prose reference

Revise an already-written prose unit in place, re-running the full Gate 1/Gate 2 cycle.

  1. Invoke prose-maker to revise per the requested change.
  2. Invoke continuity-checker for a fresh, full-unit Gate 1 audit.
  3. Confirm via [CONFIRM WRITE] / [REVISE PROSE] / [SKIP WRITE].
  4. On confirm: overwrite files via authorized scripts, run Gate 2, then /force-ledger-audit.
prose-makercontinuity-checker
/redraft-areaC-29
arg: area reference

Discard and completely redraft an entire Area's worth of prose units — not a single unit (see /revise-prose).

  1. Invoke outline-planner to re-confirm what the Area should cover.
  2. Run /next-prose once per unit, never batched — each file pair overwritten in place at Gate 2, no upfront deletion.
  3. Run /force-ledger-audit once the Area is fully redrafted.
Abort: confirm the redraft scope before overwriting.
outline-planner→/next-prose ×N→/force-ledger-audit
/redraft-chapterC-30

Discard and completely redraft an entire Chapter's worth of prose units. Same discipline as /redraft-area, scoped to the whole Chapter.

  1. Invoke outline-planner to re-confirm the Chapter's Area-by-Area plan.
  2. Archive the Chapter's existing per-Prose subtree with a timestamp — preserved, not deleted.
  3. Run /next-prose one unit at a time through every Area of the Chapter.
  4. Run /force-ledger-audit once fully redrafted.
Abort: confirm scope (exactly this Chapter) before archiving/rebuilding.
outline-planner→/next-prose ×N→/force-ledger-audit

Verification & Story-Memory

Audit & Ledger Commands

These invoke continuity-checker outside the normal Gate 1/Gate 2 flow — for a targeted check, a full-system sweep, or a manual ledger correction. /run-canon-audit is the general escalation target referenced throughout the guardrails whenever any agent or command detects an unresolved conflict.

/run-canon-auditC-10

Full canon audit — CCIA + FCIA + ALCA — across all skills, guardrails, ledgers, and written prose. The escalation target for any unresolved conflict.

  1. Invoke continuity-checker: CCIA — governance/structure integrity.
  2. Invoke continuity-checker: FCIA — across all written prose.
  3. Invoke continuity-checker: ALCA Mode B — across all ledger folders.
  4. Produce a Unified Audit Summary; log to session-log/.
Note: any finding implying a structural change is reported for explicit decision, never auto-applied.
continuity-checker ×3
/force-ledger-auditC-38

Force a full ledger audit and update across all story-memory folders — reconciles every ledger against all accepted prose. Mandatory at every Gate 2; also invokable standalone.

  1. Invoke continuity-checker to read every ledger folder and every written prose file.
  2. Verify Baseline (B) fields unmodified, Living (L) fields reflect latest accepted prose.
  3. Regenerate each folder's _index.md and the root ledger index.
  4. If a new entity type has no ledger folder: flag NEW ENTITY TYPE and stop for direction.
  5. Preview all proposed changes; require explicit confirmation before writing.
continuity-checker
/canon-checkC-20
arg: passage or claim

Check a specific passage or claim against canon without running a full audit — a targeted, single-question version of /run-canon-audit.

  1. Identify the governing Part(s)/skill(s) via the skill index + domain-ownership guardrail.
  2. Invoke continuity-checker to read those specific skills + relevant ledger entries and verify.
  3. Report VALID / INVALID with the specific rule cited — or flag genuine ambiguity / Joint Domain rather than forcing a verdict.
continuity-checker
/consequence-auditC-18
arg: character name

Audit a character's consequence arc against the Part 27 Consequence Severity Scale, to verify no consequence was silently evaded.

  1. Read the relevant ssc-character-p27-* skills.
  2. Read the character's ledger Consequence Arc section.
  3. Invoke continuity-checker to verify every consequence has an ongoing state or canon-compliant resolution shown on the page — never a silent disappearance.
  4. Report any evaded or under-resolved consequence.
continuity-checker
/ideology-auditC-17
arg: character name

Audit a character's ideology state and history against the Part 20 Ideology Ledger framework.

  1. Read the relevant ssc-character-p20-* skills.
  2. Read the character's ledger entry.
  3. Invoke continuity-checker to verify the ideology arc is internally consistent (no unearned reversal) and the Ideology Ledger section is current.
  4. Report findings; flag prose/ledger gaps for a Post-Write Ledger Update.
continuity-checker
/update-ledgerC-15
arg: entity name

Manually update a specific entity's ledger entry outside the normal post-write flow — e.g. to correct or enrich a field directly.

  1. Invoke continuity-checker to read the entity's current ledger file.
  2. Confirm the change: enriching a blank/Living field is fine; contradicting a Baseline (B) field needs a formal Canon Amendment instead.
  3. Apply the change; update Last Updated/Ledger Version; regenerate the folder's _index.md entry.
Note: never silently contradict a Baseline field — surface it as an amendment decision.
continuity-checker
/review-ledgerC-14👁 read-only
arg: entity name

Display an entity's current ledger state in full.

  1. Locate the entity's ledger file across ledger-*/ via the registries or the ledger-architecture map.
  2. Read and display in full, noting Baseline (B) vs Living (L) fields.
  3. Flag anything "not yet established" so gaps stay visible.
/load-canonC-35👁 read-only

Read-only session initialization — loads all skills, guardrails, the canon manifest, story-memory ledgers, and existing prose to establish full current state. Use at session start, or any time you want a full-state refresh rather than trusting conversational memory.

  1. Read the guardrails index and every guardrail file beneath it.
  2. Read canon-manifest/skill-index.json and the other manifest files in full.
  3. Read every ledger-*/_index.md.
  4. Read current position and all existing prose.
  5. Report a brief summary — drafts, audits, or plans nothing.

/export-chapterC-24

Assemble a Chapter's per-Prose files into a single novel-grade Chapter .docx, via the authorized script exclusively.

  1. Confirm the target Chapter's prose units are all Gate-2-complete (no pending [CONFIRM WRITE]).
  2. Concatenate existing per-Prose .docx files in canonical Area/Prose order, at 6×9 novel-grade typeset.
  3. Report the output path.
Abort: do not export a Chapter with unresolved prose units — surface which are incomplete.
/compile-phaseC-25

Assemble an entire Phase's Chapters into a single compiled .docx.

  1. Confirm every Chapter in the Phase has already been exported via /export-chapter (or export any that haven't).
  2. Concatenate the per-Chapter aggregates, prefixed with the Phase title page and icon.
  3. Report the output path.
/compile-phase-mdC-26

Markdown counterpart to /compile-phase — assembles an entire Phase's Chapters into a single compiled Markdown file.

  1. Confirm every Chapter has an up-to-date per-Prose .md file.
  2. Concatenate per-Chapter .md files in Chapter order.
  3. Report the output path.
/compile-novelC-27

Assemble every completed Phase into a single full-novel compiled document — the largest-scope compile. Confirm this is genuinely intended before running; most sessions want /export-chapter or /compile-phase instead.

  1. Confirm every Phase to be included is fully compiled via /compile-phase.
  2. Concatenate the already-compiled Phase-level documents in order.
  3. Report the output path.

  1. Confirm Phase name/number and a short descriptive prompt.
  2. Run saga_image_creator.py phase --phase N --name "…".
  3. Confirm output at phase-N/phase-icon.{png,svg}.

Changes Nothing

Read-Only / Reporting Commands

Safe to run any time. All of them read from disk rather than conversational memory — per the standing rule that the session log is a trace, never a canon source.

/statusC-13

Reports current position (Phase/Section/Novel-Part/Chapter/Area/Prose), open ledger obligations, and Section density trend.

  1. Read the actual current position on disk.
  2. Read ledger indexes for any pending Post-Write Ledger Update obligation.
  3. Invoke prose-scorer for the current Section's running aggregate, flagging any ⚠/✗ category.
  4. Report position, obligations, density trend, and outstanding Canon Variance entries.
prose-scorer
/chapter-summaryC-32
arg: chapter reference (optional)

Summarize the current or a specified Chapter's events, without reproducing full prose. Drawn from written prose files and ledger Events Log sections — not conversational memory.

/character-sheetC-19
arg: character name

Produces a readable summary character sheet from the ledger entry — identity, classification, power/capability, ideology, psychology, consequence arc, relationships, resources, narrative role, recent events. A human-friendly synthesis of /review-ledger's raw data; does not alter the ledger.

/prose-historyC-33
arg: N

Lists the last N written prose units with their references and one-line descriptions, sourced from actual file listings.

/preview-chapterC-31

Assembles the current Chapter's already-written prose units in order for review, without writing/concatenating an output document. See /export-chapter for the real file output.

⚠ Destructive — Human-Invocation Only

Reset & Rewind Commands

Every command here carries disable-model-invocation: true — an agent can never infer or auto-trigger one of these; they only run from an explicit human slash-command invocation in the current turn, and each requires an explicit confirmation before touching anything.

/hard-resetC-1🔒

The most destructive command in the system. Full wipe: clears all prose, resets all ledgers to blank/index-only, then auto-starts Prose 1.

  1. Confirm explicitly, stating plainly what will be erased.
  2. Run reset_story.py — the sole authorized reset script.
  3. Automatically proceed to /start-story for Prose 1.
reset_story.py→/start-story
/reset-storyC-21🔒

Runs the full reset_story.py (it has no prose-only mode) — clears prose and all ledgers in the same pass. Canon skills, guardrails, and the canon-manifest are untouched.

  1. Confirm explicitly, stating both prose and ledger data will be reset.
  2. Run reset_story.py in full.
/reset-phaseC-23🔒
arg: phase number

Deletes all prose in a given Phase only, then re-opens it for a fresh draft.

  1. Confirm which Phase number, and that all its prose will be deleted.
  2. Delete that Phase's prose content (icons kept or regenerated per preference).
  3. Invoke continuity-checker to run /force-ledger-audit against the now-shorter record.
continuity-checker
/reset-chapterC-22🔒

Deletes all prose in the current Chapter only, then re-opens it for a fresh draft. Scoped deletion.

  1. Confirm which Chapter is being reset.
  2. Delete the Chapter's prose files.
  3. Invoke continuity-checker to run /force-ledger-audit so ledgers don't reference now-deleted content.
continuity-checker
/reset-ledgersC-2🔒

Resets all story-memory ledgers to blank/index-only, leaving written prose untouched. Runs the equivalent clearing steps directly rather than reset_story.py (which has no ledger-only mode and would also delete prose).

  1. Confirm explicitly — prose is not affected, only ledger entity files.
  2. Perform the ledger-clearing steps directly.
  3. Recommend /force-ledger-audit afterward if prose already exists, to rebuild from what's actually on the page.
/rewind-toC-16🔒
arg: prose reference

Rolls the story back to a specific prior prose reference. Everything after it is archived as non-canonical, not deleted — superseded one unit at a time as new prose is written forward.

  1. Confirm the exact target reference; state which files will be archived.
  2. Archive prose after that reference as non-canonical pending revision.
  3. Invoke continuity-checker to run /force-ledger-audit, rolling Living (L) fields back to the target reference's state too.
continuity-checker

Mid-Execution Interrupt

Session Control

/pauseC-34

The sole mid-execution interrupt. Stops the current sequence at the next safe boundary — never mid-file-write.

  1. If a Gate 1 audit was already shown but not yet confirmed, leave it pending — resumable by the next /next-prose-family invocation, or explicitly abandoned by the user.
  2. Never performs a ledger update for anything not yet confirmed at Gate 2.
