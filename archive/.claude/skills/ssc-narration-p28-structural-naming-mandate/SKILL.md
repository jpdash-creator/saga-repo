## Area 18 — Structural Naming Mandate (Novel-Part / Chapter / Area / Prose Names)

### 18.1 — Principle

Every prose unit in the Starward Saga exists at an exact position within a six-tier narrative hierarchy — **Phase → Section → Novel-Part → Chapter → Area → Prose** — and every level of that hierarchy carries **both a number and a name**. Numbers locate the unit in the structural index; names carry its identity, theme, and function. A numbered but unnamed narrative level is structurally indistinct from every other numbered-but-unnamed level at the same tier, which erodes the reader's (and the author's) ability to hold the story's shape. The Starward Saga therefore mandates that **Novel-Part, Chapter, Area, and Prose each carry an explicit name** at every Gate 1 chat delivery and every Gate 2 file write, without exception.

Phase names and Section names are already Locked Canon under Part 30 (e.g., Phase 1 = "The Roots of Becoming"; Section 1 = "The Citadels of Morning"). This Area extends the naming discipline downward to the four sub-Section tiers, which are governed by Part 2 (novel structure) and Part 28 (Negotiable Canon instancing).

### 18.2 — The Four Named Tiers

**Novel-Part Name.** Every Novel-Part within a Section carries a name. Novel-Parts are the largest sub-Section narrative units (Part 2 Area 1 Tier 3). A Section's Novel-Parts are thematically coherent sub-arcs of the Section's overall narrative, and the Novel-Part name captures the sub-arc's defining movement. *Example form:* "The Morning of the Twin Oath," "The Bells Before the Envoys," "First Light on the Sapphire Basin."

**Chapter Name.** Every Chapter within a Novel-Part carries a name. Chapters are the primary narrative pacing units (Part 2 Area 1 Tier 4). Chapter names function as the reader's in-book navigational headings and must carry enough specificity to distinguish the Chapter from its neighbors while remaining evocative rather than functional. *Example form:* "The Brass Bell and the Alloy Bell," "The Gallery of Seven Portraits," "Three Days East of Threefold."

**Area Name.** Every Area within a Chapter carries a name (an "Area Description" in Part 2 Rule 6.3.2 terminology). Areas are the scene-or-scene-cluster units within a Chapter (Part 2 Area 1 Tier 5) and each Area is a coherent narrative event — a scene, a sustained sequence, a focused beat cluster. The Area name captures the Area's specific narrative event in a brief nominal phrase. *Example form:* "Varya Wakes to the Paired Bells," "The King and Queen at the Balustrade," "The Alliance at the Threshold."

**Prose Name (Prose Slug).** Every Prose unit within an Area carries a name (a "Prose Slug" in Part 1 Rule 7.1.1 terminology). Prose units are the atomic writing units (Part 2 Area 1 Tier 6) — one Prose = one author-session writing pass = one file pair (`prose-NNNNN.docx` + `prose-NNNNN.md`). The Prose name is the tightest nominal handle on the Prose's specific content and is what the author and reader use to identify this exact Prose among its sibling Prose within the same Area. *Example form:* "The First Morning," "The Two Lights in the Gallery," "What the Sash Remembers."

### 18.3 — The Naming Mandate (Categorical)

**Rule 18.3.1 — Names Are Mandatory, Not Optional.**
At every Gate 1 chat delivery for any Prose unit produced by any of the 13 prose-producing commands, the Gate 1 Position Header Block must carry **all four** tier names (Novel-Part, Chapter, Area, Prose) in addition to the Phase and Section names. A Position Header Block that displays only numbers, or that displays an em-dash or "TBD" or "(if any)" placeholder in any of the four tier-name fields, is a Rule 18.3.1 violation and the Post-Draft Audit FAILS.

**Rule 18.3.2 — Names Must Be Established Before Gate 1.**
Before Gate 1 Chat Delivery, the author must establish the Prose unit's Novel-Part, Chapter, Area, and Prose names. For the very first Prose of a new narrative container (e.g., the first Prose of Chapter 1, Area 1, Novel-Part 1 of a Section), the names are authored as part of the Prose planning sequence that precedes the Pre-Output Audit. For every subsequent Prose in the same container, the existing container's name is inherited unchanged; only the new Prose's own name is freshly authored. Names, once established, are Base Information (B) in the Session Ledger (Part 1 Area 5) and are preserved across `[HARD RESET]` cycles.

**Rule 18.3.3 — Names Must Appear In Gate 2 File Writes.**
At every Gate 2 file write, the file-level Chapter Header Block (Part 2 Rule 6.3.1 / 7.2.1) must carry the Chapter name, the Area Divider (Part 2 Rule 6.3.2 / 7.2.2) must carry the Area name, and every Prose file (`prose-NNNNN.docx` and `prose-NNNNN.md`) must carry the Prose name in the canonical Prose Title Block immediately preceding the Prose body. The Novel-Part name is carried in the Chapter Header Block's Novel-Part sub-line. A Gate 2 file write that omits any of these four names is a Post-Write Audit FAIL and the Ledger Update is held until the file is corrected.

**Rule 18.3.4 — Names Must Appear In The Ledger Reference Code.**
The canonical Reference Code `Phase.Section.Part.Chapter.Area.Prose` (e.g., `1.1.1.001.1.00001`) identifies the Prose by number. When recording Prose events in any ledger (character, location, faction, world, etc.), the event row must carry the Reference Code **and** the full name-chain (Phase Name / Section Name / Novel-Part Name / Chapter Name / Area Name / Prose Name) so the ledger is readable without cross-referencing the structural index. Ledger event rows that carry only the numeric Reference Code without name accompaniment are a Rule 18.3.4 violation.

### 18.4 — Name Authoring Standards

**Rule 18.4.1 — Register and Length.**
Names at all four tiers follow the Starward Saga's literary register (Part 2 Area 2, Part 29 dialogue voice) — evocative, image-bearing, avoiding functional or database-like formulations. A Chapter name of "Chapter 1" (bare number) is invalid. A Chapter name of "Introduction" (functional label) is invalid. A Chapter name of "The Brass Bell and the Alloy Bell" (image-bearing) is valid. Suggested length ranges: Novel-Part names 3–9 words; Chapter names 2–8 words; Area names 3–10 words; Prose names 2–8 words.

**Rule 18.4.2 — Uniqueness Within Container.**
Names must be unique within their immediate container. Two Chapters within the same Novel-Part may not share a Chapter name. Two Areas within the same Chapter may not share an Area name. Two Prose within the same Area may not share a Prose name. Across containers, identical names are permitted but discouraged for clarity.

**Rule 18.4.3 — Thematic Coherence With Parent Tier.**
A Chapter's name should be in evident thematic coherence with its Novel-Part's name, which should be in evident coherence with its Section's name, which should be in evident coherence with its Phase's name (all governed by Part 30). The name-chain read as a whole should read as a narrative ladder, not as a set of disconnected labels.

**Rule 18.4.4 — Stability After First Use.**
Once a name has been used in any Gate 1 chat delivery or Gate 2 file write, it is stable. Renaming a previously-delivered Novel-Part, Chapter, Area, or Prose requires a formal Canon amendment and a coordinated rewrite of every downstream reference (ledgers, other Prose that reference the name, file-system folder names). Casual renaming is prohibited.

### 18.5 — Interaction With Other Rules

- **Part 1 Rule 7.1.1 (Gate 1 Position Header Block):** Extended by Rule 18.3.1 — the Position Header Block's Novel-Part / Chapter / Area / Prose fields are **not** optional "if any" placeholders under this Area; they are mandatory. The Part 1 template is amended to reflect this.
- **Part 1 Rule 7.1.1(k) (Two-Audit Mandate):** Post-Draft Audit (Pass 1) includes a check that all four tier names are present and conform to Rules 18.3.1 and 18.4.1–18.4.4. Post-Write Audit (Pass 2) includes a check that all four names appear in the written files per Rule 18.3.3.
- **Part 2 Area 6 (Docx File Structure):** The Chapter Header Block (Rule 6.3.1), Area Divider (Rule 6.3.2), and Prose Title Block (new) all carry names per Rule 18.3.3.
- **Part 2 Area 7 (Markdown File Structure):** The mirroring rules (Rules 7.2.1, 7.2.2, and new Prose Title Block rule) apply to `.md` files identically.
- **Part 28 Area 3 (Naming Freedom Law):** Novel-Part, Chapter, Area, and Prose names are Negotiable Canon under Area 3 — the author is free to invent them within the register and coherence standards of this Area 18. Once established, they become Base Information (B).
- **Part 28 Area 17 (Lore Creation Law):** Names at the four tiers are *not* named entities in the Area 17 sense (they are narrative-structural labels, not in-world proper nouns) and do not trigger the Area 17 Lore Mandate. However, if a Chapter name or Area name uses an in-world proper noun (e.g., "The Twin Oath Shrine" as an Area name), that in-world noun's Area 17 lore entry must already exist per the Lore Mandate.

### 18.6 — Failure Grades

- **Minor.** One missing name at one tier in a single Prose delivery, correctable by adding the name before Gate 2.
- **Major.** Multiple missing names in a single Prose delivery, or persistent missing names across multiple Prose deliveries in the same session.
- **Critical.** Delivery of any Prose to file with one or more tier names missing from the on-disk files. Post-Write Audit FAIL; Ledger Update held; file pair must be rewritten with names before the Prose is accepted into the canonical body.

### 18.7 — Tentative-Count Range Discipline (Position Header Block)

The Position Header Block (Part 1 Rule 7.1.1) carries an ordinal-of-total count under each tier name. The four narratively-tentative tiers — **Novel-Part, Chapter, Area, Prose** — must render their total field as a **low–high range** in the form `[M_low]–[M_high]` (using a single en-dash `–`, not a hyphen `-` and not an em-dash `—`), reflecting that the total is an estimate within a band, not a precise number. The two Locked Canon tiers (Phase, Section) render their total as a single integer per Part 30. A single-integer total at any of the four tentative tiers is non-compliant under Rule 7.1.1 (v2.12); a `~` "approximation" prefix is also non-compliant — the range itself carries the tentativeness. If no range estimate has yet been authored for a given tier, the `of [M_low]–[M_high]` clause is omitted and the line reads simply `*Tier [N]*`. The Tier Scope Brackets emitted after every Prose (Part 2 Area 9 Rule 9.10.1) are the authoritative range source — the Position Header Block range fields draw their values directly from the Tier Scope Brackets that the planning instrument maintains. A Position Header Block range that diverges from the active Tier Scope Bracket range for the same tier is a Rule 7.1.1(k) Audit Pass 1 FAIL.
